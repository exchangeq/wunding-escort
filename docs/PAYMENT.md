# 收款与在线支付

系统里订单是「业务状态」和「付款状态」分开记的：业务走待接单 / 护航中 / 已完成，付款走待付款 / 待确认 / 已到账 / 已退款。后台可以单独确认到账，不影响排单进度。

## 一、收款码（默认）

适合个人号、工作室小号，不依赖任何支付服务商。

1. 后台「站点设置 - 收款设置」，勾上「开启收款码付款」；
2. 上传微信、支付宝收款码（建议 300×300 以上的 PNG，别用截图压缩过的）；
3. 填一句付款说明，比如「付款备注订单号，核对后开始排单」；
4. 保存。

用户下单后，详情页的成功弹窗和订单查询页都会出现付款面板：切换微信/支付宝、复制订单号、上传付款截图。上传后订单的付款状态变成「待确认」，后台订单列表里点「确认到账」即可。

注意：

- 收款码是给人看的，系统不校验截图真伪，确认到账这一步必须人工对一遍账单；
- 上传的截图存在 `data/uploads/`，和商品封面同一个目录，备份时一起拷；
- 单张截图限制 3MB，格式只收 PNG / JPG / GIF / WEBP，会校验文件头。

## 二、易支付（彩虹易支付标准接口）

有商户号的话可以开在线支付，用户在付款面板点按钮直接跳转到支付页，回调自动改状态。

### 后台配置

| 字段 | 说明 |
| --- | --- |
| 网关地址 | 商户后台给的接口地址，例如 `https://pay.example.com`；填到 `submit.php` 也行，程序会判断 |
| 商户 PID | 商户 ID |
| 商户密钥 | 商户 KEY，只存在 `data/db.json`，前台接口不会返回 |
| 支付方式 | 支付宝 / 微信，对应接口的 `type` |
| 按钮名称 | 前台显示的文字 |

勾选「启用在线支付」并填全网关、PID、密钥才会生效，否则前台只显示收款码。

### 接口约定

- 发起支付：`GET/POST {网关}/submit.php`，参数 `pid`、`type`、`out_trade_no`、`notify_url`、`return_url`、`name`、`money`、`sign`、`sign_type=MD5`
- 异步通知：`{站点}/api/pay/notify`，GET 或 POST 均可，返回纯文本 `success` / `fail`
- 同步跳回：`{站点}/api/pay/return`，302 到订单查询页

签名：把所有参数（去掉 `sign`、`sign_type` 和空值）按参数名 ASCII 升序拼成 `k=v&k=v`，末尾直接拼商户 KEY，取 MD5 小写。

```text
sign = md5("money=168.00&name=xxx&notify_url=...&out_trade_no=WD...&pid=1001&return_url=...&type=alipay" + KEY)
```

回调校验会核对三件事：签名、`trade_status`（`TRADE_SUCCESS` 或 `TRADE_FINISHED`）、金额和订单金额是否一致（误差 1 分以内）。同一个订单重复回调不会重复记账。

### 上线前

1. **必须是公网能访问的域名**，回调地址不能是 `127.0.0.1` 或内网 IP，否则收不到异步通知；Termux 本地跑建议用 Cloudflare Tunnel，把隧道域名作为站点域名。
2. 站点上 HTTPS，Nginx 反代时保留 `X-Forwarded-Proto`，不然拼出来的回调地址是 http。
3. 支付平台要求备案域名 / 商户资质，按对方要求准备；别用「第四方代收」「跑分」这类通道，资金和账号都不安全。
4. 退款在支付平台商户后台操作，操作完回后台把订单标成「已退款」，两边对上账。
5. KEY 泄露等于别人能伪造到账通知，换服务器、换维护人员时记得在商户后台重置。

## 三、对账建议

- 每天把后台「已到账」的订单和支付平台账单对一遍，重点看金额和订单号；
- 收款码方式的订单，确认到账前先看截图里的金额、备注订单号、收款方名称；
- `data/db.json` 和 `data/uploads/` 每天备份，订单和凭证都在这；
- 退款、补差价这类操作，在订单备注里写清楚，别只改状态。

## 四、冒烟测试

仓库自带脚本会把两种付款方式都跑一遍：

```bash
bash scripts/smoke.sh python
bash scripts/smoke.sh go
```

脚本里会临时把易支付网关指到一个假地址，用测试 KEY 自己算签名调 `/api/pay/notify`，验证「正确签名通过、错误签名拒绝」。真实网关不用参与测试。
